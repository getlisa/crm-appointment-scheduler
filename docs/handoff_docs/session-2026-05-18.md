## What Was Done This Session

### 1. Cross-account booking blocked (backend + prompt)

Removed the CROSS-ACCOUNT BOOKING section from `docs/buildops/retell_single_prompt.txt` — it allowed an identified caller to switch to a different company's account mid-call, causing bad job creation.

**Two-layer enforcement:**
- **Prompt**: CROSS-ACCOUNT BOOKING section deleted. The agent is no longer guided through this path.
- **Backend guard** in `src/services/buildops/handlers/fuzzy-lookup.ts`: `handleLookupFuzzy` returns an error immediately if `session.matchedCustomerId` is already set. Even a direct API call will be rejected.

**Allowed flows going forward (hard requirement):**
- Flow 1: Unknown number → `lookup_customer_fuzzy` → associate with existing account → optionally `add_representative`
- Flow 2: Identified number → `prepare_job` only
- Nothing else.

### 2. `call_ended` writes `disconnection_reason` as session status

`buildops_inbound_calls.status` is no longer always written as `'ended'`. The handler now reads `disconnection_reason` from the Retell payload and uses it directly.

```
user_hangup | agent_hangup | call_transfer | voicemail_reached |
inactivity | machine_detected | max_duration_reached |
concurrency_limit_reached | dial_busy | dial_failed | dial_no_answer |
error_inbound_webhook
```

Falls back to `'ended'` if `disconnection_reason` is absent.

**Files changed:**
- `src/services/buildops/types.ts` — `InboundCallStatus` extended with all Retell `disconnection_reason` values
- `src/routes/buildops.ts` — `call_ended` handler reads `disconnection_reason`, writes it as `newStatus`
