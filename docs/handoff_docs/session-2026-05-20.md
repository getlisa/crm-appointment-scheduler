### fn/* `callId: undefined` — root cause identified (not yet fixed in code)

Retell sends **two different payload shapes**:

| Event | Shape |
|---|---|
| Lifecycle (call_started, call_ended) | `{ call: { call_id, from_number, to_number }, ... }` |
| Function tool call (fn/*) | `{ call_id: "call_xxx", args: { ... } }` ← root level, no nested `call` |

All fn/* handlers extract `callId` via `body.call?.call_id` — returns `undefined` for function calls since there is no `call` object. This causes `resolveSession` to fail on both paths (direct lookup and phone fallback), producing `error: session not found` before any business logic runs.

**Fix needed** in `src/routes/buildops.ts` — every fn/* handler (5 locations):
```typescript
// BEFORE
const call = body?.call as Record<string, unknown> | undefined;
const callId = call?.call_id as string | undefined;

// AFTER
const call = body?.call as Record<string, unknown> | undefined;
const callId = ((body.call_id ?? call?.call_id) as string | undefined);
```

### Incremental cron sync — rep detection overhaul

**Problem**: BuildOps does NOT update `customer.audit.lastUpdatedDateTime` or `customer.version` when a representative is added. The dirty-detection loop had no signal to re-fetch reps for unchanged customers, and newly added reps (not yet in DB) were invisible to the DB-side dirty check.

**Changes made** to `src/services/buildops/supabase/buildops-cron/index.ts`:

1. **Fix 1 — Empty `representative_ids` as dirty signal**: DB select now includes `representative_ids`. Any customer with an empty rep list in DB is always marked dirty → reps re-fetched on next cron run. Catches "first rep ever added to a customer".

2. **Fix 2 — Periodic full rep sweep every 2h**: Added `sweepAllReps()` function. Reads per-customer rep COUNT from DB, fetches actual reps from API, rebuilds any customer where count differs. Throttled by `last_rep_sweep_at` column in `buildops_tenants`. Between sweeps, Fix 1 covers the common case.

3. **Fix 3 — Deleted resource handling**:
   - Customers with `audit.deletedDateTime` set are deleted from `buildops_customers` during the page loop
   - Properties with `audit.deletedDateTime` are filtered out of `fetchAllProperties` before upsert

4. **`updateRepresentativeIds` SELECT chunked** — was doing one `.in('customer_id', allIds)` query which hits PostgREST's URL length limit when called with many customer IDs. Now chunks at 50 IDs per query.

**Schema addition required** (run in Supabase before deploying cron):
```sql
ALTER TABLE buildops_tenants ADD COLUMN IF NOT EXISTS last_rep_sweep_at TIMESTAMPTZ;
```

## Call Architecture
```
call_inbound  → create row: session_id=UUID, retell_call_id=NULL; phone lookup → set matched_customer_id
call_started  → findActiveByCallerAndTenant (DESC) → setRetellCallId(session.sessionId, realCallId)
fn/*          → body.call_id (root) → getInboundCall(retellCallId) → fallback; all DB updates use session.sessionId
call_ended    → getInboundCall(callId) → setCallStatus(session.sessionId, disconnectionReason) → fallback
```

## Cron Sync Architecture
```
incrementalSync()
  1. Check last_rep_sweep_at → set doRepSweep flag (every 2h)
  2. Load DB customer map (ts, version, repIds)
  3. Fetch all live properties → dirty by property.lastUpdatedDateTime
  4. Query DB reps → dirty by rep.updated_at > customer watermark
  5. Page all API customers:
       - skip deleted (audit.deletedDateTime) → delete from DB
       - dirty if: dirtySet || ts advance || version advance || !db || repIds.length === 0
       - rebuild dirty: re-fetch reps, upsert customer row, re-insert reps
  6. Property cleanup (remove DB props not in API)
  7. If doRepSweep: sweepAllReps() — compare rep COUNT (api vs db), rebuild changed → update last_rep_sweep_at
```
