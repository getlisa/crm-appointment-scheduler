### 5. Two production bugs fixed (NOT YET COMMITTED — blocked on migration)

Root cause identified from a live Retell call:

**Bug A — `customer_property_id` always undefined**

Retell sends function params under `body.args` (for `args_at_root: false` tools), but `normalizedBuildopsPayload` was returning the whole body, so `args.customer_property_id` resolved to `body.customer_property_id = undefined`.

Fix: `normalizedBuildopsPayload` now checks `body?.args` before falling back to root.

```typescript
// src/routes/buildops.ts:31
function normalizedBuildopsPayload(req: { body?: unknown }): unknown {
  const body = req.body as { arguments?: unknown; args?: unknown } | undefined;
  return body?.arguments ?? body?.args ?? body ?? {};
}
```

Affects all `args_at_root: false` functions: `prepare_job`, `confirm_customer`, `match_property`, `add_representative`.

**Bug B — Stale session returned by fallback (+ architectural fix)**

`findActiveByCallerAndTenant` returned the *oldest* active session for a caller when 2 existed (stale UUID + current call), causing function calls to be applied to the wrong session.

Root cause: `retell_call_id` was overloaded as both the internal session key (UUID set at `call_inbound`) and the direct-lookup key (real `call_xxx` ID set at `call_started`). Until the swap fired, the direct lookup failed and the fallback could pick the wrong row.

Fix: split into two columns:
- `session_id` — stable UUID assigned at `call_inbound` (used as WHERE key for all updates)
- `retell_call_id` — Retell's real `call_id`, NULL until set at `call_started` (used for direct lookup only)

**Schema change required — run migration before deploy (see Pending section A).**

## Session/Call Architecture (as of this session)

```
call_inbound fires
  → create row: session_id = Retell UUID, retell_call_id = NULL
  → phone lookup → set matched_customer_id if found

call_started fires  
  → findActiveByCallerAndTenant (ORDER BY created_at DESC) → get session
  → setRetellCallId(session.sessionId, realCallId)
  → row now: session_id = UUID, retell_call_id = "call_xxx..."

fn/* fires
  → getInboundCall(callId)  ← direct lookup by retell_call_id (fast path)
  → fallback: findActiveByCallerAndTenant if not found
  → all DB updates use session.sessionId as WHERE key

call_ended fires
  → getInboundCall(callId) → setCallStatus(session.sessionId, disconnectionReason)
  → fallback to caller lookup if retell_call_id lookup misses
```
